# TASK-028 第一轮用户研究计划

状态：等待真实参与者  
研究对象：当前《人生分岔机》Demo  
产品定义：[`../PRODUCT-BRIEF.md`](../PRODUCT-BRIEF.md)

## 研究目标

这轮研究不问“你喜不喜欢这个产品”，而是确认五件事：

1. 目标用户做高成本职业选择时，真正缺少的是什么；
2. 他们现在怎样使用知乎、朋友意见和利弊表；
3. 三世界和分岔回声是否帮助他们看到机会成本；
4. 想法检验和代价报告是否让问题变得更具体；
5. 七天实验是否具体到第二天真的愿意执行。

## 样本结构

计划招募 8 名参与者，均不参与本项目开发。

| 分组   | 人数 | 条件                                             |
| ------ | ---: | ------------------------------------------------ |
| 选择前 |    3 | 未来 90 天内需要决定换工作、读研、创业或城市选择 |
| 选择中 |    3 | 正在比较两个以上真实选项，已有截止日期或外部压力 |
| 选择后 |    2 | 最近 6 个月完成类似选择，仍记得当时的信息缺口    |

共同筛选条件：

- 20–32 岁，毕业后 0–8 年的知识工作者；
- 至少有两个现实可行选项；
- 选择结果存在明显时间、经济或关系成本；
- 过去一年使用过知乎搜索经验，或会主动阅读陌生人的长经验内容。

排除：当前项目成员、已经完整看过 Demo 讲稿的人、只需查询事实的问题，以及医疗、法律、投资或即时危机类决定。

## 研究方法

### A. 半结构化访谈，8 人

- 单次 25–35 分钟；
- 先聊真实经历，不先介绍产品；
- 重点记录实际行为、具体时刻和最后缺失的信息；
- 结束前才用一句话介绍产品，并听参与者复述理解。

### B. 无讲解可用性测试，至少 5 人

- 单次 20–30 分钟；
- 从首页或 `/demo` 开始，研究者不解释术语和按钮；
- 参与者边操作边说出正在理解什么；
- 卡住 90 秒后才能提供最小提示，并记录提示内容；
- 完成后立即复述分岔回声、想法检验、报告和七天实验。

可以让同一参与者先访谈、短暂休息后再做测试，但两段记录必须分开。

## 筛选问题

1. 你最近半年做过，或未来三个月要做哪类重要选择？
2. 当时是否有至少两个可以实际选择的方案？
3. 你为了这个问题查过哪些信息或问过哪些人？
4. 你是否在知乎搜索或阅读过类似经历？大概做过什么？
5. 你是否看过或参与过《人生分岔机》的开发？

满足前四项且第五项为“否”时优先招募。

## 招募文案

> 我们正在测试一个帮助人梳理职业选择的小工具，想找最近半年做过，或未来三个月要做换工作、读研、创业、城市选择的人聊一聊。全程约 45–60 分钟，包括一次经历访谈和一次产品体验。没有标准答案，也不会记录真实姓名、单位或精确收入。你的反馈只用于改进产品，可以随时停止或要求删除记录。如果你愿意参加，请告诉我你面对的大致选择类型和方便的时间。

## 单场流程

| 时间       | 内容           | 研究者动作                   |
| ---------- | -------------- | ---------------------------- |
| 0–3 分钟   | 同意与说明     | 解释用途、匿名方式和退出权利 |
| 3–25 分钟  | 真实经历访谈   | 追问具体行为，不评价决定     |
| 25–28 分钟 | 休息与任务说明 | 只给目标，不介绍功能         |
| 28–50 分钟 | 无讲解体验     | 观察、计时、记录原话         |
| 50–60 分钟 | 复述与收尾     | 检查理解、复用意愿和下一步   |

## 数据处理

- 参与者只使用 `P01`–`P08` 编号；
- 不在仓库保存真实姓名、联系方式、单位和精确收入；
- 原始录音不提交 GitHub，转写后删除身份信息；
- 每条结论必须能对应参与者编号和脱敏原话；
- 团队解释单独写在“分析”栏，不改写成用户原话；
- 参与者提出删除时，同时删除会话记录和引用索引。

## 结论门槛

- “重复痛点”：至少 3 名参与者独立提到或在行为中出现；
- “严重可用性问题”：至少 2 人无法继续，或 1 人触发不可恢复失败；
- “高价值瞬间”：至少 3 人能准确复述，并能说明对自己有什么用；
- 单人意见保留为线索，不直接进入 P0；
- 团队原有判断即使听起来合理，也必须标记为假设，直到得到数据支持。

## 完成条件

- 8 份有效访谈；
- 5 份有效无讲解测试；
- 至少 3 个有原话支持的重复痛点；
- 一份按影响和证据强度排序的问题列表；
- 明确 TASK-029 在 AI 职责设计中优先解决哪项用户问题。
