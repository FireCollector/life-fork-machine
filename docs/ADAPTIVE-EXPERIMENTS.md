# TASK-039｜动态实验适配说明

## 它解决什么

七天实验不能只把固定任务卡逐日推给用户。真实生活里会遇到对方不回复、材料拿不到、条件变化，或时间和成本开始失控。TASK-039 会把这些**明确记录**转成下一天的建议，但不替用户判断人生结论。

## 输入边界

每次真实模式记录新增两项可选结构化输入：

- **证据信号**：支持原假设、与原假设冲突、或仍然信息不足；
- **实际阻碍**：未回复、材料缺失、条件变化、时间/成本超标或其他。

“感受”仍会被保存，但它不是客观证据。只有用户明确选择的证据信号，或明确记录的阻碍，才会触发对应的建议规则。

## 规则与举例

| 记录情况                    | 下一天建议方向                     | 解释边界                         |
| --------------------------- | ---------------------------------- | -------------------------------- |
| 对方未回复                  | 设定明确回复时限，同时找备用来源   | 沉默是信息缺失，不是拒绝或支持   |
| 材料拿不到                  | 先确认材料获取时间或找可替代记录   | 不用空白脑补结论                 |
| 条件变化                    | 把变化写为新约束，只重估受影响部分 | 旧计划不自动作废，也不能直接沿用 |
| 时间/成本超标、吃力或被卡住 | 把动作缩小到有上限的一小步         | 不要求用户“补回”当天进度         |
| 证据冲突                    | 查一条关键反例，暂停扩大承诺       | 不忽略冲突，也不仓促反向下注     |
| 证据支持                    | 补一项可复核细节                   | 单条支持信息不等于结论成立       |

## 用户始终可控制

调整被保存为 `suggested`，并且记录原计划、推荐动作、触发日期和解释。用户可以：

1. **采用建议**：将建议写入下一天待办；
2. **保存自定义**：用自己的具体动作替代建议；
3. **保持原计划**：拒绝建议；
4. **撤销调整**：在下一天真正记录前回到原任务。

所有状态都保存在本地会话和 JSON 导出中。刷新不会重新生成建议，也不会改变已经接受、改写或撤销的选择。

## 产品边界

- 仅对 `real` 模式生效；Demo 继续使用固定快进脚本。
- 本任务使用确定性规则，不把模型猜测、用户情绪或未记录的信息当作事实。
- 这是低成本验证动作的调整器，不是医疗、法律、投资或职业决策的自动建议器。
