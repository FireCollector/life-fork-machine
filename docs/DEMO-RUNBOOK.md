# 3 分钟现场演示 Runbook

目标：让评委在 3 分钟内看到“知乎经验 → 三条人生 → 现实验证”的完整闭环。现场只走固定 `/demo`，不要临时输入长议题。

## 演示顺序

1. **开场 0:00–0:20**：说出困境——“稳定高薪和跟领导创业，真正难的是不知道哪些话算数。”强调产品不替用户下注，而是先把代价和证据摊开。
2. **校准 0:20–0:35**：展示用户当前现金缓冲、家庭压力和最在意的指标。点击继续。
3. **承诺之夜 0:35–1:00**：选择“先签一份四周验证清单”，说明这不是怂，而是把“领导会给股权”变成可核对的条件。
4. **证据熔炉 1:00–1:20**：选择一个知乎经验卡，指出作者、原文和适用边界；再展示“证据支持/冲突/暂不清楚”不是二元裁决。
5. **想法检验 1:20–1:40**：点击“等待新情况”，说明系统也允许“事情真的和预期一样”，这时会给出确认动作，而不是强行制造反转。
6. **报告 1:40–2:05**：快速扫过三世界雷达、得到/失去/仍不知道和未选择路线的分岔回声。强调每一项都由前面的选择动态计算。
7. **七天实验 2:05–2:35**：展示与路线匹配的实验包，完成 7 天记录，选择“最接近证据”的结果。解释它是现实中的小步验证，不是形式化彩蛋。
8. **分享与收束 2:35–3:00**：打开脱敏分享卡，展示议题、路线、关键选择、实验结论和下一步；收束为“把一次人生豪赌，改成一次可复盘的现实实验”。

## 评委问答备忘

**问：这和普通人生模拟有什么不同？**

答：普通模拟给一个结局，我们保留没走的路，并把最关键的假设落到七天现实实验；用户带走的是证据，不是一个看似权威的答案。

**问：AI 在哪里？**

答：AI 负责把知乎社区经验和用户议题整理成候选叙事、角色和实验；内容经过来源追溯与人工门禁，最终状态转换由可复现规则引擎负责，避免模型随意改写事实。

## 现场保险

- 提前打开生产链接，另备 `/demo` 本地地址。
- 不依赖 OAuth、实时搜索或外部模型；网络抖动时仍可完成主流程。
- 若页面刷新，从首页重新进入 `/demo`；若需展示知乎素材审核，单独打开 `/evidence-review`。
