# 观点与证据整理

`TASK-033` 位于“检索知乎候选”和“生成候选场景”之间。它不是给用户一份“综合答案”，而是把来源中相同的提醒、真正的分歧和不适用的条件分开，让后续剧情或实验只能使用已追溯、已审核的内容。

## 使用流程

1. 在 `/topic-lab` 写下议题并确认可编辑的决策简报。
2. 点击“获取知乎候选”。只有本次实际返回的候选会进入下一步。
3. 至少有 3 条来源时，点击“整理 N 条来源”。服务端把摘要和来源 ID 交给现有 AI 网关。
4. 页面会呈现三个固定视角：共同提醒、保留分歧、适用边界。
5. 点击每条观点下的作者链接可以回到知乎原文；审核者可以修改条件、风险，或通过/排除观点簇。

## 数据和安全边界

- `EvidenceOrganization` 强制每条观点至少绑定一个本次候选来源 ID；不在输入集内的引用会被 Schema 拒绝。
- AI 只负责按引用组织文本，不能修改游戏状态、发布场景或给出最佳路线。
- 页面只显示摘要和原文跳转，不复制不必要的全文。
- 来源少于三条或简报未确认时，接口会明确拒绝请求。实时 AI 不可用或输出未通过 Schema 时，接口只会把**本次检索**的摘要和用户的核验项组成“规则辅助整理”，页面会显式标注该模式；它不会用静态内容冒充 AI 结论。
- 人工编辑会保存字段、前值、后值、审核者和时间；不会抹掉原始 AI 结果的修订痕迹。

## 接口

`POST /api/evidence/organize` 接收：

```json
{
  "brief": "已确认的 DecisionBrief",
  "evidence": { "status": "ready", "items": ["至少三条本次知乎候选"] }
}
```

成功响应是 `EvidenceOrganization`。其中 `provenance: "ai-assisted"` 表示模型输出已通过引用和 Schema 校验，`"rules-assisted"` 表示当前来源的透明回退。它们都是临时审核数据，TASK-034 才会消费已通过的观点簇来生成候选 `ScenarioPack`。
