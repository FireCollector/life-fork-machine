# 从知乎链接开始

`/zhihu-import` 让用户从已经存在的公开讨论开始，而不必把同一个问题再描述一遍。

## 支持与边界

- 支持 `https://www.zhihu.com/question/:id`、`/answer/:id` 和 `https://zhuanlan.zhihu.com/p/:id`。
- 链接会规范化，去掉追踪参数；非知乎、非 HTTPS 或不支持的路径会在发起请求前被拒绝。
- 服务端仅调用已配置的知乎官方公开检索能力，以“规范链接、内容 ID、可选关注方向”为检索词。不会抓取网页、不会读取私信、收藏、关注或任何私有账号数据，也不需要 OAuth。
- 当前公开检索能力没有通用的“按 URL 读取全文”接口。因此结果分为 `exact`（索引返回了这条链接）、`related`（只找到了相关公开讨论）和 `none`。`related` 永远不会被显示成原链接内容。
- 仅保存标题、作者、原文链接、摘要、互动数、抓取时间和来源 ID；不复制不必要的正文。

## 观点如何影响推演

用户必须从两条不同来源中选择：

1. **这个观点最像我**：把这条经验转成“它适用于我的前提是什么”。
2. **这个观点让我不舒服**：把这条反例转成“它提示的风险会不会落到我身上”。

选择会作为 `CommunityLensSelection` 与本次来源一起带入 `/topic-lab`。候选三幕 API 将它们写入 `DecisionBrief` 的待核对假设与未知项，再生成路线和七天实验草稿。它们不是投票、事实结论或最佳路线；所有生成结果仍是待人工审核的 `ScenarioPack`，不会进入固定 Demo。

例如，同一个“是否换城市”的知乎讨论中，选择“先保留现金流”的回答，会要求核对该做法的前提；选择“家庭支持突然缺失”的回答作为不舒服的反例，会把对应的脆弱点带进实验问题。交换两条选择，候选包的关键假设和实验问题会随之变化。

## 失败与恢复

| 状态           | 页面行为                                       |
| -------------- | ---------------------------------------------- |
| 链接不支持     | 说明只支持的问题、回答、专栏路径；不发起检索。 |
| `empty`        | 说明没有公开候选；不补造观点。                 |
| `rate-limited` | 显示知乎额度/频率限制，允许稍后重试。          |
| `unavailable`  | 明确本次未获取结果，不以旧缓存冒充。           |
| 少于 3 条来源  | 停在观点页，不能进入候选三幕。                 |

## 通用性约束

这个能力只依赖 `DecisionBrief`、`EvidenceSource`、`CommunityLensSelection` 与 `ScenarioPack` 的通用合同；没有创业、读研、城市等专有字段。它适用于普通生活、职业、升学和迁移等非高风险议题。高风险主题仍由 `DecisionBrief` 的安全门禁拦截，不进入普通推演。
