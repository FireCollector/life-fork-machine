# 从决策结果到知乎表达草稿

TASK-042 的目标不是替用户在知乎发布，而是把“读到经验—做一次现实验证—写下自己学到什么”的过程变成一个可编辑、可检查的个人草稿。

## 使用路径

1. 在已完成的结果页点击“整理为知乎回答草稿”。
2. 页面只在本机携带路线、已选行动、关键假设、实验状态和本次引用的知乎来源。
3. 在 `/zhihu-draft` 编辑标题和正文，检查“我验证到的事”“我还不知道的事”和下一步是否符合自己的真实经历。
4. 打开来源链接核对语境，完成四项隐私与责任确认。
5. 仅在没有敏感字符串且确认完成后复制草稿；用户自行决定是否在知乎发布。

## 默认排除与隐私审核

初稿不会带入：

- `session ID`、本地档案 ID、账号或 OAuth Token；
- 每日个人备注、情绪记录和未公开材料；
- 真实姓名、联系方式、精确收入、家庭成员细节和公司内部信息。

编辑后会检测常见手机号、邮箱、身份证号和精确金额模式。检测结果只给出类别，不回显可能的敏感片段。自动检测不是完整隐私保证，因此复制前仍要求用户明确确认身份、家庭/公司信息、引用语境和“不会代发”四项。

## 来源与事实边界

引用列表只保留本次推演所引用来源的标题、作者和原文链接。它们是阅读线索，不代表事实结论或“多数人意见”。草稿将社区经验、个人实验记录和未验证事项分开写；没有实验结果时明确写为进行中，不把过程包装成结论。

## OAuth 边界

当前项目保持 OAuth 关闭。本页没有登录、同步或发布接口，也不会读取用户数据。

未来如需授权同步或辅助发布，必须同时满足：用户主动选择该能力、应用部署到已登记的公网 HTTPS 回调、应用凭证只在服务端保存、用户亲自完成知乎授权确认。授权被取消、过期或失败时必须停止访问，不能退回到 Access Secret 所属账号，更不能自动发布。由于当前协议缺少完整的 state/PKCE/撤销闭环，未在此版本提供生产 OAuth 发布能力。
