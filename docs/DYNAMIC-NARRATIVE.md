# 动态叙事与快照（TASK-035）

`/topic-lab` 的候选剧本现在可以在不发布、不改写正式游戏会话的前提下，针对用户正在看的路线、幕和小动作生成一段短叙事。

## 用户会看到什么

1. 选择一条候选路线、一幕和一个小动作；
2. 点击“看看这一步该问什么”；
3. 看到一段受控的候选叙事、一个最值得问的问题，以及三类线索：**支持线索、冲突线索、暂时不清楚**；
4. 每张线索卡都能回到本次检索到的知乎原文；
5. 同一路线/幕/动作会复用本机快照。刷新不会让已经看过的剧情换一套说法；换路线或动作才会产生新快照。

“支持”不代表系统认定用户会成功，“冲突”也不代表一定会失败。它们只是提示：哪条候选来源可参考、哪种条件不能照搬、哪件事还需要本人拿材料确认。

## 数据与边界

```text
已确认简报 + 已检索来源 + 待审核 Candidate ScenarioPack + 当前路线/幕/动作
                                      │
                                      ▼
                         /api/narrative（候选表达）
                           │                     │
                       AI 合同通过            AI 不可用/结构失败
                           │                     │
                           └──────► 动态叙事快照 ◄──────┘
                                      │
                              localStorage 保存同一上下文
```

- API 只接收已确认的 `DecisionBrief`、3–12 条当前来源、同一简报的 `CandidateScenarioPack` 和有效上下文。
- AI 调用复用既有 `AiGenerationRequest`，任务为 `explain-candidate`；它仍只能返回带来源的候选包，不能改写 `GameSession`、预算、审核状态或发布状态。
- 所有叙事引用必须属于候选剧本的 `sourceIds`。外来 ID、敏感文本、跨剧本或跨世界动作都会被拒绝。
- AI 输出正常时标记为 `ai-assisted`；超时、限流、不可用或结构失败时改用 `rules-assisted` 模板，并把失败事实告诉用户。
- `publicationAllowed` 恒为 `false`。候选表达需和路线、实验一起通过人工审核，才可能进入正式三幕引擎。

## 快照策略

快照键由版本、`briefId`、`packId`、`worldId`、`sceneId` 和 `actionId` 确定，不含当前时间。页面将合法快照存为 `life-fork-machine:narrative-snapshots:v1`：

- 相同上下文优先读取已保存结果，不再次请求 AI；
- 修改路线、幕或动作得到不同键，因此可以出现不同叙事和追问；
- 网络失败不会覆盖已有快照，也不会写入半成品；
- 本机存储只是演示会话恢复，不等于云端同步或正式发布记录。

## 验证重点

`tests/dynamic-narrative.test.ts` 覆盖：路线/动作变化、同一上下文稳定性、三类线索、跨世界动作拒绝、外来来源拒绝，以及 AI 请求仍停留在候选合同中。
