# 系统架构

## 一句话

《人生分岔机》是一个“内容包驱动、规则确定性优先、知乎素材可追溯”的 Next.js 互动叙事应用。它把知乎社区经验转化为可参与的故事和可执行的小实验，契合“跨次元游乐场”对 AI 互动叙事、角色扮演和社区内容再利用的期待。

## 数据流

```text
场景包 / 知乎检索快照
          │
          ▼
      Zod 校验
          │
          ▼
  规则引擎（状态、分岔、实验、报告）
          │
          ▼
   React 页面与交互组件
          │
          ▼
 localStorage 会话（可恢复、可分享脱敏）
          │
          ├── 三幕推演
          ├── 假设检验
          ├── 动态七天实验
          ├── 三世界报告
          └── 知乎素材审核与发布门禁
```

## 目录职责

- `content/scenarios`：议题、角色、世界线、行动、后果与实验模板。内容可替换，代码不必重写。
- `content/evidence`：知乎来源卡和官方检索快照，记录来源、作者、原文链接、摘要与适用边界。
- `src/features/game`：`schema.ts` 定义数据契约，`engine.ts` 负责确定性状态转换，`experiment.ts` 与 `evidence-*` 负责实验和审核纯函数。
- `src/features/ai`：只定义 AI 请求、候选、来源校验与失败合同；不保存或修改游戏会话。
- `src/components/experience`：把规则映射为可操作的三幕界面、报告、分享卡和审核工作台。
- `scripts`：校验场景包和刷新知乎候选素材，不直接绕过审核发布。
- `tests`、`e2e`：覆盖规则、隐私、审核门禁和关键浏览器路径。

## 关键设计取舍

1. **先规则、后模型**：没有 AI Provider 或 OAuth 时，Demo 仍能完整运行；未来接入模型只负责生成候选文本，最终状态转换仍由规则引擎决定。
2. **事实与想象分开**：知乎素材用于提供经验线索；“另一条人生”和未来来信是反事实叙事，不冒充现实预测。
3. **证据先审核**：搜索快照只进入候选区。审核状态、版本号和通过门槛都写入状态，保证演示链路可解释。
4. **隐私最小化**：本地会话只存演示所需状态；分享卡经过脱敏，不携带 session ID、账号和用户当天备注。
5. **议题可扩展**：`/topic-lab` 先产出候选结构，审核后生成 `ScenarioPack`，即可复用同一套三幕、报告和实验引擎。
6. **AI 候选隔离**：模型输出永远是带来源的候选，只有规则引擎可变更会话；完整边界见 [`AI-ARCHITECTURE.md`](AI-ARCHITECTURE.md)。

## 与知乎生态的连接

项目选择“跨次元游乐场”赛道，把知乎社区中分散的真实经验变成可验证的互动叙事素材：用户不是被动读答案，而是带着自己的问题进入角色，在做选择、看后果、做七天小实验的过程中，把社区经验转化为行动证据。这同时对应 AI 互动叙事、观点排练和知乎内容再利用三个方向。

## 安全边界

- OAuth 默认关闭；Access Secret 只由官方 CLI 管理，不进入前端。
- 不把知乎内容整篇复制进场景，只保留必要摘要、引用指针和适用条件。
- 报告中的金额、时间和压力值是演练参数，不构成职业、投资或法律建议。
