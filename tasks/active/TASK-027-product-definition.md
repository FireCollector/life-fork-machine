# TASK-027｜重新冻结产品定义与成功指标

- 状态：In Progress
- 负责人：Codex
- 创建日期：2026-09-07
- 开始日期：2026-09-07
- 依赖任务：D01–D26 Demo 基线

## 目标

形成一份团队可以共同使用的长期产品定义，明确目标用户、核心任务、价值边界、当前用户旅程和第一版成功指标。

## 为什么现在做

当前 Demo 已经能稳定演示，但真实 AI、多议题和七天跟踪都会扩大产品范围。先冻结产品定义，后续技术选择才有统一判断标准。

## 输入与输出

- 输入：现有 README、MVP PRD、当前 Demo、最终评分报告和产品 Roadmap。
- 输出：`docs/PRODUCT-BRIEF.md`、`docs/USER-JOURNEY.md` 和 `docs/METRICS.md`。

## 范围

- 允许修改：产品与研究文档、README 中的产品定位、任务板和验证记录。
- 不允许修改：游戏规则、页面交互、AI Provider、依赖和生产配置。
- 本任务不做：接入模型、执行用户访谈、界面改版和新增场景。

## 工作清单

- [x] 明确第一目标用户和暂不服务的人群。
- [x] 定义用户进入产品时的核心任务和离开时应得到的结果。
- [x] 画出当前主流程，标注输入、输出、价值和风险。
- [x] 定义关键假设命中、证据理解和实验启动等第一版指标。
- [x] 统一 README 与长期 Product Brief 的核心表述。

## 边界情况

- [x] 医疗、法律、投资等高风险决定不进入普通推演。
- [x] 只有一个可行选项或只想获得事实答案的问题不强行生成三世界。
- [x] 没有知乎证据或证据冲突时，明确显示信息不足。

## 验收标准

- [x] 文档用一句话和 30 秒版本说明给谁用、解决什么、为什么使用。
- [x] 每项后续能力都能对应一个用户结果或明确风险。
- [x] 产品边界明确写出“不预测人生、不输出最佳选择”。
- [x] TASK-028 可以直接使用目标用户、用户旅程和指标开展研究。
- [ ] 至少一名队友只读 Product Brief 后，能准确复述产品定位。

## 验证

- 自动检查：Markdown 格式、链接、项目质量门禁和 `git diff --check`。
- 人工检查：至少一名队友只读 Product Brief 后复述产品。
- 证据目录：`verification/TASK-027/`

## 回滚与阻塞

- 回滚方式：仅回退本任务文档，不影响运行中的 Demo。
- 阻塞条件：团队对第一目标用户或产品边界存在根本分歧。
- 解除条件：完成一次团队产品范围讨论并记录选择理由。
