# TASK-027｜重新冻结产品定义与成功指标

- 状态：Ready
- 负责人：待开始时确认
- 创建日期：2026-09-07
- 依赖任务：D01–D26 Demo 基线

## 目标

形成一份团队可以共同使用的产品定义，明确目标用户、核心任务、价值边界和第一版成功指标。

## 为什么现在做

当前 Demo 已经能稳定演示，但真实 AI、多议题和七天跟踪都会扩大产品范围。先冻结产品定义，后续技术选择才有统一判断标准。

## 输入与输出

- 输入：现有 README、MVP PRD、Demo、最终评分报告和后续 Roadmap。
- 输出：`docs/PRODUCT-BRIEF.md`、体验流程图和指标字典。

## 范围

- 允许修改：产品与研究文档、README 中的产品定位、任务板和验证记录。
- 不允许修改：游戏规则、页面交互、AI Provider、依赖和生产配置。
- 本任务不做：接入模型、用户访谈执行、界面改版和新增场景。

## 工作清单

- [ ] 明确第一目标用户和暂不服务的人群。
- [ ] 定义用户进入产品时的核心任务和离开时应得到的结果。
- [ ] 画出当前主流程，标注输入、输出、价值和风险。
- [ ] 定义关键假设识别率、实验启动率等第一版指标。
- [ ] 统一 README、PRD 和产品 Brief 的表述。

## 验收标准

- [ ] 团队成员能在 30 秒内用同一种说法解释产品。
- [ ] 每项后续能力都能对应一个用户结果或明确风险。
- [ ] 产品边界明确写出“不预测人生、不输出最佳选择”。
- [ ] TASK-028 可以直接使用本任务的用户定义和研究问题。

## 验证

- 自动检查：Markdown 格式、链接和 `git diff --check`。
- 人工检查：至少一名队友只读 Product Brief 后复述产品。
- 证据目录：`verification/TASK-027/`

## 回滚与阻塞

- 回滚方式：仅回退本任务文档，不影响运行中的 Demo。
- 阻塞条件：目标用户无法收敛为一个主要群体。
- 解除条件：完成一次团队产品范围讨论并记录选择理由。
