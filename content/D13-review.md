# D13 实验反馈交互验收记录

## 目标

让七天现实实验不再只有一条退出规则，而是可以在 Demo 里模拟三种结果，并立即看到下一步建议。反馈是本地演示状态，不代表系统真的等待了七天或在后台跟踪现实。

## 已完成

- `sevenDayExperiments` 新增 `nextStep` 数据结构，为支持、冲突、暂时不清楚分别提供下一步建议。
- 创业议题的 9 个实验模板全部补齐三种下一步建议。
- 结果页增加“模拟反馈”区域，提供三个可点击选项：证据支持、证据冲突、暂时不清楚。
- 选择反馈后展示“已记录演示反馈”、对应含义和下一步建议。
- 使用 `aria-pressed` 与 `aria-live`，方便键盘操作和读屏工具理解反馈状态。
- 明确标注“演示用”，并说明不会真的等待七天，也不会在后台持续跟踪。
- 复制文本结果会同步带上演示反馈、反馈含义、下一步建议和演示免责声明。

## 验收结果

- S03 数据校验通过：9 个实验均具备三种下一步建议。
- TypeScript 检查通过。
- ESLint 检查通过。
- 39 项测试全部通过，覆盖三个反馈按钮、选择冲突结果、下一步建议和复制文本。
- 生产构建通过。
- 固定 Demo 结果页的既有回归基线保持通过；本轮交互由组件测试覆盖。

## 有意留到 D14 / 冲刺阶段的内容

- 反馈尚未写回长期会话账本，不影响本次已完成的路径结果。
- 暂不接入真实计时器、通知、用户账号或后台任务。
- 暂不让反馈结果重新计算雷达分数；后续可在通用议题结构稳定后再设计反馈对状态向量的影响规则。
