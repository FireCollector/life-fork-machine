# 人生分岔机 · Life Fork Machine

> 在做出不可逆决定前，先把另一种人生走一遍。

《人生分岔机》是面向知乎 AI 黑客松“跨次元游乐场”赛道打造的可运行互动叙事产品。它从知乎社区的真实经验出发，处理“稳定高薪工作与跟领导创业如何选择”这类现实困境，把一次纠结拆成三条可比较的路线、一个需要验证的关键假设，以及一个可以在现实中执行的七天实验。

它不预测用户的未来，也不输出“最佳答案”。用户会看到每条路的收益、代价、未知和证据边界，然后自己决定下一步。

## 为什么做它

现实中的难题通常不是缺少建议，而是：

- 只听到成功故事，看不到没走的那条路要付出什么；
- 把“领导会给股权”“家里能扛住”这类想法当成事实；
- 做完一次选择就结束，无法把结论带回现实继续验证。

项目用“知乎经验 → 推演 → 假设检验 → 三世界报告 → 七天现实实验”的闭环，把抽象纠结变成可检查、可复盘的小步骤。它不是替用户算命，而是把社区内容变成一次能亲手走完、还能带回现实验证的体验。

## Demo 能力

- 三幕推演：承诺之夜、证据熔炉、想法检验。
- 三条世界线：留守轨道、全押新局、搭桥试水。
- 分岔回声：未选择的世界不会消失，可以查看反事实剖面并重新推演。
- 假设检验：支持、冲突、暂时不清楚三种结果，不强行给二元答案。
- 动态七天实验：根据路线、行动、假设结果和状态压力选择不同实验，并逐日记录行动与证据。
- 三世界代价报告：雷达图、得到/失去/仍不知道、盲点和未来来信。
- 知乎素材审核：使用官方开放平台检索快照，展示原文、作者、适用条件和审核提醒。
- 发布门禁：素材必须逐条审核，至少通过 3 条且处理完待审核项，才能发布候选剧本版本。
- 隐私安全分享：分享卡不包含 session ID、账号信息或用户当天备注。
- 离线优先：没有 AI Provider 或 OAuth 时仍可稳定运行完整 Demo。

## 立即体验

### 1. 安装依赖

```bash
npm install
```

### 2. 启动开发服务器

```bash
npm run dev
```

打开 <http://127.0.0.1:4173/>。

### 3. 推荐演示入口

直接打开 <http://127.0.0.1:4173/demo>，使用固定种子进入推荐路线，适合现场讲解和反复演示。

其他入口：

| 地址                  | 用途                         |
| --------------------- | ---------------------------- |
| `/`                   | 首页与项目介绍               |
| `/demo`               | 固定 90 秒队友 Demo          |
| `/topic-lab`          | 预设或任意问题的候选结构生成 |
| `/evidence-review`    | 知乎素材审核、版本与发布门禁 |
| `/calibrate`          | 约束校准                     |
| `/play/[sessionId]`   | 三幕推演                     |
| `/result/[sessionId]` | 代价报告与七天实验           |
| `/api/health`         | 应用健康检查                 |

固定 Demo 的逐步点击路线见 [`content/D08-demo-kit.md`](content/D08-demo-kit.md)。

## 技术结构

```text
Next.js App Router
├── src/components/experience     页面与交互
├── src/features/game              Schema、规则引擎、实验和分享纯函数
├── content/scenarios               场景、三幕行动、结果模板
├── content/evidence                知乎来源卡与检索快照
├── scripts                         内容校验与知乎快照刷新
└── tests + e2e                     单元、组件和浏览器验收
```

核心原则：

1. 内容和引擎分离。替换场景包即可扩展到“读研还是工作”等议题。
2. 规则确定性优先。状态变化、实验选择和结果报告都可复现。
3. 来源可追溯。知乎素材保留来源 ID、作者、原文链接和适用边界。
4. 事实与反思分开。未来来信是情景文本，不是现实预测。
5. 审核先于发布。候选内容不会绕过人工审核直接进入正式推演。

更完整的系统说明见 [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)。

## 刷新知乎素材快照

项目使用官方 `zhihu` Skill 管理 CLI 和 Access Secret。Access Secret 不写入源码、浏览器或日志。

```bash
node scripts/fetch-zhihu-evidence.mjs \
  --query "跟领导创业 辞职 股权 现金流 如何选择" \
  --count 10
```

脚本会生成 `content/evidence/zhihu-search-latest.json`。检索结果只是候选素材，仍需在 `/evidence-review` 逐条审核。当前仓库默认关闭 OAuth：`hackathon.config.json` 中 `oauth.enabled` 为 `false`。

## 当前边界

- 当前冻结的正式场景是“稳定高薪工作与跟领导创业如何选择”。
- `/topic-lab` 可以生成任意议题的候选结构，但正式三幕引擎仍要求审核后的场景包。
- 会话默认保存在当前浏览器 `localStorage`，没有登录和云端同步。
- 知乎素材以本地快照方式进入 Demo，不承诺页面实时搜索。
- 结果中的数值是决策演练模型，不是职业、投资或法律建议。

## 后续路线

1. 把知乎检索、去重、人工审核和场景发布做成服务端流水线。
2. 为审核通过的议题生成完整 `ScenarioPack`，接入正式三幕引擎。
3. 在事实边界内增加在线 AI 个性化叙事，并保留确定性规则兜底。
4. 增加匿名云端会话、协作决策和可撤销的 OAuth 个性化能力。
